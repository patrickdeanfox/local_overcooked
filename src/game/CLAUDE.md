# src/game — the presentation arm

Everything the player sees and touches that is not the raw simulation: Phaser scenes, the HUD, the 3D kitchen renderer, settings and progress persistence, the pause menu, the debug overlay, level hot reload and the F8 note reporter. This arm never decides a game rule; it reads `SimState` and draws it.

Owner: the presentation agent. Files: `src/game/**` except `scenes/ControllerScene.ts` (input arm). Tests: `tests/game.*.test.ts`, `tests/playnotes.test.ts`. Branch prefix `game/` (or `ui/`, `render/`). Read `docs/DESIGN.md` once for the whole picture and `docs/WORKFLOW.md` for how PRs land.

## Files
Top level
- `types.ts` — scene payloads `GameSceneData` and `ResultsSceneData`.
- `settings.ts` — presets, the custom difficulty numbers (`CUSTOM_FIELDS`, `stepCustom`, `customModifiers`), assists, the five mechanics switches (`Mechanics`, `MECHANIC_IDS`, `MECHANIC_NAMES`, `mechanicModifiers`, `mechanicSummary`; `docs/MECHANICS.md`), seed modes, audio switches, chef picks; `loadSettings` / `saveSettings` with an injectable storage. Pure, no Phaser. Mechanics fold into `presetModifiers()` like assists but `isAssisted()` ignores them: a run with mechanics on is saved and earns stars.
- `progress.ts` — best score, stars and plays per level, stars kept per preset; `recordRun`, `isUnlocked`, `unlockingStars` (which skips the tutorial kitchens: `levelCountsTowardUnlock`, ids under `TUTORIAL_ID_PREFIX`). Pure.
- `tutorial.ts` — the walkthrough a tutorial kitchen carries in `LevelDef.tutorial`: `fillLabels` (the `{pickup}` placeholders), `goalMet` (one case per `TutorialGoal`), `TutorialRunner` (intro → steps → done or skipped; `observe(state, events, dtSec)` after every stepped frame, advancing through every goal the frame satisfied). Pure, no Phaser; `tests/game.tutorial.test.ts` walks every tutorial kitchen through the real Sim with it.
- `storage.ts` — guarded `localStorage` and value coercion; a private window, a full quota or a hand-edited value must never take the game down.
- `audioBus.ts` — the one `AudioBus` for the whole page, mute persistence, gesture resume, the M key.
- `levelHotReload.ts` — the only browser module allowed to import `src/levels`; `currentLevels()`, `defaultLevelId()`, `onLevelsHotReload()`.
- `playnotes.ts` — F8 reporter: overlay, screenshot with the 3D canvas composited in, context provider, `POST /api/playnotes`, offline queue.

`scenes/` — `BootScene` (textures, then all models, then Title), `TitleScene` (level list without the tutorial kitchens, plus Tutorials, players, difficulty, Chefs, Settings, Controllers rows), `TutorialsScene` (the tutorial kitchens as a `LevelList`, the selected one's rules and record under it, a Back row; confirm starts the kitchen), `SettingsScene` (Seed, Seed number, Free play, the three assists, the five mechanics, Custom difficulty, Music, Sound effects, Back; the list packs to `menuSpacingDense` once the rows would reach the hint line), `CustomDifficultyScene` (one row per sim number; the preview line under the list is computed by a throwaway `Sim` on the first level, so it cannot disagree with the game), `ChefsScene` (live 3D preview on the shared stage), `GameScene` (the loop), `ResultsScene` (the only writer of progress).

`ui/` — `theme.ts`, `Hud.ts` (order cards with the dish icon, a row of one icon per ingredient, the name and the time bar; score, timer, prep hint; a card re-reads its order's recipe every frame, and on an `orderRewritten` event flashes the card art amber for `ORDER_REWRITE_FLASH_SEC` while the new icons drop in, then wears an "86" tag while `originalRecipeId` is set), `MenuList.ts`, `LevelList.ts` (a name wider than `ROW.nameMaxPx`, the custom kitchens' titles, is scaled down to fit before the theme column), `menuInput.ts` (`MenuInput` from `PlayerInput`, `KeyboardNav` from raw keys, merged into rising edges), `PauseMenu.ts` (an overlay, not a scene: the sim simply stops stepping), `TutorialOverlay.ts` (draws a `TutorialRunner`: the rules panel that holds the sim still until confirm, back skips; then the step banner along the bottom, a finished step lingering green with a tick, the outro for `outroHoldMs`; the pointer is a Graphics triangle placed by `KitchenRenderer.tileToScreen(x, y, lift)` every frame), `DebugOverlay.ts` (F3 or backtick).

`render/` — `KitchenRenderer.ts` (SimState → Three scene plus a thin Phaser overlay) and `three/`: `stage.ts` (the WebGL canvas behind Phaser, camera fit, lights, projection, low-fx), `loader.ts` (glTF load, normalise, cache per `ModelRole`), `tiles.ts` (stations, ground, theme dressing, sliders, gates, knives), `items.ts` (item views and their change signature), `chefs.ts` (rig, skin, toque, idle/run crossfade), `fx.ts` (fire, smoke, steam, spray sprites).

`debug/fakeState.ts` — a plausible `SimState` for F4 smoke tests of the renderer and HUD.

## Boundary
- Imports: `Sim`, `SIM_DT`, types, `TIMER_WARNING_AT`, `RECIPES` from `src/sim`; `createInputManager` and the edge-latch helpers from `src/input`; `sfxForEvent`, `createAudioBus`, `AudioBus` from `src/audio`; `generateTextures`, `TEX`, `CHEF_SKINS`, `MODELS`, `MODEL_ROLES`, `PALETTE`, `soupColor` from `src/art`; `LevelDef` (type) and `parseGrid` from `src/levels/schema`; `SCENE`, `STORAGE_KEYS`, sizes from `src/config`; `log`.
- Never import `src/levels` anywhere but `levelHotReload.ts`, or a level JSON edit becomes a full page reload instead of an in-place rebuild. The accept path must be a string literal.
- `SCENE` keys live in `src/config.ts` and the scene list in `src/main.ts`; both are integrator-owned, so a new scene is a two-arm PR.

## The frame (`GameScene.update`)
Poll input once → if the F8 form is open, render the current state and return → merge menu navigation → paused: drive the pause menu, no stepping → a tutorial's rules panel up (`tutorial.isBlocking`): hand it the nav, no stepping → else `runSim`: clamp the frame to 0.25 s, latch edges before the loop, step at `SIM_DT` up to 30 times, rising edges on the first sub-step only, drop the accumulator when saturated → `getState()` once → check level end → `render`: F4 swaps in the fake state, `getTargetTile` per chef, then `kitchen.draw`, `hud.update(state, events)`, `debugOverlay.update`. Every `SimEvent` goes to `recentEvents` (for notes), through `sfxForEvent` to the bus, and to `tutorial.observe` with the frame's stepped seconds. `render` suppresses the HUD's prep hint while a tutorial is active (its banner says the same thing) and draws the overlay last; `buildTutorial` runs after the input manager exists (the text carries the player's button names) and again on hot reload. HUD flourishes read events (`serve` popup, `orderExpired` flash); 3D effects are derived from state, not events (fires, steam, spray). Nothing allocates per frame: step inputs, latches and the poll array are reused.

## Renderer
- World units: one tile is one unit, x right, z toward the camera, y up. A level change rebuilds the `TileSet` and refits the camera; a frame only updates offsets, items, chefs, effects.
- Views are pooled: tile items by tile index, held items by chef and thrown items by flight id (drawn on a sine arc over the flight's range), reused while `itemSignature(item)` is unchanged (cook progress is bucketed so a pot is not rebuilt every frame); chef rigs by index, pedestrians by id. A dashing chef's rig stretches along its heading (`ChefRig.setDashing`) and leaves floor dust; a falling chef is hidden until it respawns and bursts into dust as it goes. A `gap` tile has no ground plane, so the backdrop shows through as the hole.
- Mechanics (`docs/MECHANICS.md`): `KitchenRenderer` takes `TileFlags` (`passThroughShelf`, from `sim.getEffectiveSettings()` in `GameScene.buildLevel`) because a `shelf` tile changes with the switch. Walls are `wallBlock(height?)`: the kit's `wall` role scaled to a full one-tile footprint (its slab is 0.22 tiles deep and reads as a line when seen along it), full height for an interior `void` tile (a void off the outer ring with a walkable neighbour, drawn on floor ground so Hatch Row's divider is solid) and for a shelf while the switch is off (over `TEX.shelfClosed` ground), counter height for an open shelf so items rest on its top: the divider reads as a wall with dips in it. The `shelf` role (the order window) is loaded but unused. Wall blocks are yawed by `wallAxisYaw`, along their wall; every other station uses `frontYaw`. `oneTileWide` squeezes `trayRack` and `delivery` to one tile; the door's item slot sits `DELIVERY.crateForward` in front of it and holds the `deliveryCrate` model (`drawDelivery`) while a `restocks` entry has arrived. A `TrayItem` view is the `tray` role with its load laid along it at `TRAY.spread`, smaller by `TRAY.itemScale`, and its signature is the joined signatures of the load; a held tray shakes for the rest of `chef.wobble` (`WOBBLE`). Two held plates are the existing plate stack (`plateView` with `count` 2). Overlay (`drawBars`): a crate with `stock` shows a fill bar (green, amber, red by `STOCK` fractions), and a `TEX.chalk86` image (`drawChalk`, `CHALK.lift` above the surface) hangs while `stock === 0`; the unloading bar (green) is drawn on the door from the due restock's `unloaded`, which persists when the hands leave, so it does not depend on `chef.action`; `lifting` (blue) reuses the action bar at the target tile; the "x2" badge (`ASSIST_BADGE`) sits right of the bar and lingers `lingerSec` after `chef.assisting` clears (the sim deletes the flag every step, so a badge tied to the flag alone vanishes the frame the keys lift). Constants for all of these live in the `Mechanics spec` block at the top of `KitchenRenderer.ts` and in `three/tiles.ts` (`FOOTPRINT`, `DELIVERY`) and `three/items.ts` (`TRAY`).
- Phaser overlays (progress bars, stack badges, the debug grid) get screen positions from `Stage.project`, which maps through the perspective camera into Phaser's logical 1280x800 space, so they survive FIT scaling. The camera reserves `CAMERA.hudTopPx` and `hudBottomPx` for the HUD band: change the HUD layout and change those.
- Themes are `THEMES` in `three/tiles.ts` (`default`, `treacle-town`, `savoury-seas`: backdrop, floor, back wall). Unknown themes fall back to `default`. `themeSceneHeight` feeds the camera fit. Road tiles at an edge get asphalt and parked cars on every theme.
- `loader.ts` loads every role in `MODEL_ROLES` once at boot; a failed or early request becomes a magenta placeholder box and a log line, never a crash. Skinned meshes have frustum culling off. Instances share geometry and materials, so tint through `tintObject`.
- Low-fx mode (half pixel ratio, no shadows) switches on under `navigator.webdriver` or a HeadlessChrome user agent so the playtest harness keeps its frame budget.

## Persistence
`local-overcooked.settings.v1` (players, preset, custom difficulty numbers, seed mode and number, free play, assists, mechanics, audio, chefs; a version mismatch resets to defaults, a save without `mechanics` reads them as off) and `local-overcooked.progress.v1` (per level: best score, stars, plays, stars by preset; unlocks count Normal and harder only). Mute is a separate raw `'1'`/`'0'` key. Progress is written in exactly one place, `ResultsScene`, before its menu is built and never for an assisted run. A tutorial run is saved like any other but `unlockingStars` leaves it out; results after a tutorial say so, offer "Next tutorial" (the next among the tutorials only, as "Next level" walks the rest) and "Back to tutorials". Both load functions take an injectable storage; the tests rely on it.

## How to add
- **A scene**: `scenes/X.ts` extending `Phaser.Scene` with the standard skeleton (`createInputManager`, `MenuInput` plus `KeyboardNav`, `installAudioGestureResume` and `installMuteToggle` pushed into `disposers`, `events.once(SHUTDOWN, cleanup)`, a `ready` flag cleared before every `scene.start`); a `SCENE` key in `src/config.ts` and the class in `src/main.ts` (integrator); a payload in `types.ts`; a row that opens it.
- **A HUD element**: a constants block at the top of `ui/Hud.ts`, create in the constructor and add to `root`, update in `update()`, destroyed with `root`. Icons must be `TEX` keys the art arm generates.
- **A model on a tile or item**: the role belongs to `src/art/models.json`; here add the `buildStation` case (plus `GROUND_TEXTURE`, `SOLID_FOR_WALL`) in `three/tiles.ts`, or the `INGREDIENT_ROLE` / `BURGER_LAYER_ROLE` entry or a `buildItemView` branch in `three/items.ts`, and make `itemSignature` change whenever the look changes.
- **A theme**: a `THEMES` entry; report its height in `themeSceneHeight` if it adds tall scenery. Roadmap item 6 moves themes to data.
- **An effect**: sound is `sfxForEvent` (audio arm); a HUD flourish is `Hud.handleEvents`; a 3D effect is a `drawX` in `KitchenRenderer` derived from state plus a spawner on `FxPool` with a `TEX` sprite.
- **A settings row**: `RowId`, the `ROWS` order and `DESCRIPTIONS` in `SettingsScene.ts`, a case in `item(id)`, every mutation through `applySettings()`; a persisted field also needs `Settings`, `DEFAULT_SETTINGS`, coercion in `loadSettings` and `settingsSummary`. The playtest scripts reach Settings rows by cursor count, so add rows after the assists, not before; script `20` counts eleven rows down to Custom difficulty since the mechanics rows landed.
- **A tutorial kitchen**: a level JSON under `src/levels/tutorial/` with `game: 'tutorial'`, `mechanics` forcing its switch, `timerStartsOnFirstServe: true` and a `tutorial` block (levels arm; goal vocabulary in `docs/LEVEL_SCHEMA.md`). Nothing here changes: the Tutorials page lists whatever `currentLevels()` reports as `tutorial`, `GameScene` builds the overlay for any level with a `tutorial` block. A new goal type is a `TutorialGoal` member (schema) plus a `goalMet` case in `tutorial.ts` and a `validateLevel` rule.
- **A custom difficulty number**: a `Modifiers` field (sim arm) first; then a `CustomDifficulty` key, a `CUSTOM_FIELDS` row with its range and step, a `DEFAULT_CUSTOM` entry, a `describeModifiers` line, and a `preview` case in `CustomDifficultyScene.ts`.

## Tests and checks
`tests/game.settings.test.ts`, `tests/game.progress.test.ts` (fake and throwing storages), `tests/game.tutorial.test.ts` (`fillLabels`, the runner, every `goalMet` case, and a walkthrough of each tutorial kitchen through the real Sim with teleported chefs and real button presses), `tests/playnotes.test.ts` (`buildNote`, queue helpers: keep them importable in Node), `tests/art.test.ts` for the `TEX` contract. There are no unit tests for scenes, the renderer or the HUD: `npm run typecheck` plus the headless harness are the checks. Every feature has a script in `tools/playtests/` (`07` covers the scene flow, `15` to `19` cover menus, settings, assists and chefs, `20` the custom difficulty page, `22` the order cards, `26` the five mechanics: the Settings rows, then a QA kitchen with the tray, the shelf, two plates, the 86 chalk mark and rewritten ticket, the delivery and the x2 badge, `27` the tutorials: the title row, the Tutorials page, the tray walkthrough step by step with the pointer, the closing banner, a solo chop assist run skipped from the panel, the results after a tutorial); add one for anything new and read the screenshots. `26` opens Settings by `scene.start` rather than by cursor count, which the other scripts should copy once the level list grows past six rows.

## Gotchas
- A menu choice can start another scene mid-update; check `ready` after every handler.
- `KeyboardNav` tracks its own previous state and never uses `JustDown`, whose flag is consumed by the first reader.
- The Title settings list is moved, not rebuilt, because a rebuild from inside a row callback destroys the list mid-handle.
- Nudging or typing the seed pins `seedMode` to `fixed`; Esc reaches menus as the pause action.
- The 3D kitchen is its own canvas: the note screenshot composites it first, and the F8 form takes the keyboard in the capture phase so nothing reaches Phaser.
- Dead surface (no `noUnusedLocals`): `TILE` import in `DebugOverlay`, `CHEF_COLORS` in `ui/theme.ts`, `Stage.dispose`, `loader.modelsReady`, `loader.modelScaleFactor`, `KitchenRenderer.scaleValue`.
